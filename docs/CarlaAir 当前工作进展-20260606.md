### 第二阶段：车载 TCP-Lite 学习式驾驶

当前已接入：

```text
车载 RGB + speed + navigation_command
  -> TCP-Lite
  -> trajectory + steer/throttle/brake
```

当前主要模型：

```text
models/tcp_lite_combined_vehicle_traj10_control1_e40.pt
```

当前控制模式：

```text
vision_model_control_mode = trajectory_model
vision_navigation_command = lane_follow
```

本轮稳定性修正：

- 首帧转向加入速率限制，避免车辆从静止开始直接打满舵导致早期甩出车道。
- 路口低速恢复：路口内 `lane_follow/straight` 场景如果车速过低且未刹车，会临时提高 throttle，避免长时间停在路口。
- 验证后删除了过激的 lane departure guard 分支，因为真实运行中它会放大偏离并导致停车。

相关提交：

```text
54d7839 recover tcp lite low speed junctions
08bffba rate limit tcp lite initial steering
8aaf302 guard tcp lite lane departures
a257f77 avoid braking in tcp lane guard
ee07823 remove overactive tcp lane guard
```

其中 `8aaf302` 和 `a257f77` 是中间探索提交，最终通过 `ee07823` 删除了验证效果不好的偏离保护，只保留真实验证有效的首帧限速和路口低速恢复。

### 第三阶段：YOLO11n 辅助感知

当前已接入：

```text
  -> YOLO11n
  -> obstacle / traffic / attack-pattern detection
  -> safety gate / confidence gate
```

当前模型路径：

```text
models/yolo11n.pt
```

本轮修正了一个真实运行中的误检问题：在车载 RGB 视角下，YOLO 有时会把画面右下边缘的大块自车车身或背景区域误检成 `car`，触发 `vision_obstacle` 后导致 ego 车刹停。

修正位置：

```text
carlaair_active_world/vision_models/yolo11_obstacle.py
```

新增几何过滤逻辑：

- 如果 bbox 紧贴右边界；
- bbox 中心位于右侧；
- bbox 面积过大；
- 则判定为 ego-camera 下沿自车体或背景误检，不作为 forward obstacle。

保留行为：

- 真实近距离居中车辆 bbox 仍会被判定为 forward obstacle。
- traffic light / stop sign 仍作为 traffic diagnostics 输出。
- YOLO detections 仍记录，过滤只影响是否触发安全刹停。


### 第四阶段：UAV-BEV 融合

当前已完成轻量 UAV-BEV 融合原型：

```text
UAV RGB
  -> BEVFormer-Lite style feature extractor
  -> global BEV-like feature

车载 TCP/local visual control + UAV global BEV-like feature
  -> fusion correction
  -> vehicle control
```

当前不是完整训练版 BEVFormer 大模型，而是一个 BEVFormer-Lite 风格的轻量原型，目标是先打通真实 CARLA/AirSim 闭环：

```text
AirSim UAV RGB
  -> extract_uav_bev_feature()
  -> CachedUAVBEVProvider
  -> VisionEgoDriver observation["uav_bev"]
  -> TcpLiteVisionPolicy._uav_bev_correction()
  -> fused vehicle control
```

新增核心文件：

```text
carlaair_active_world/vision_models/uav_bev.py
configs/scenarios/town10hd_vision_tcp_lite_yolo_uav_bev.json
configs/scenarios/town10hd_vision_tcp_lite_yolo_uav_bev_stable.json
```

`uav_bev` 特征包括：

```text
road_confidence
center_bias
forward_density
left_right_balance
feature
```

融合方式是低幅度 steer correction，不替代车端 TCP-Lite 主控制，避免 UAV 图像短时异常时破坏 clean 场景。

关键参数：

```json
{
  "uav_enabled": true,
  "uav_control_enabled": true,
  "uav_bev_fusion_enabled": true,
  "uav_bev_camera_name": "front_center",
  "uav_bev_refresh_hz": 2.0,
  "uav_bev_min_confidence": 0.20,
  "uav_bev_steer_gain": 0.06,
```

### 终端 3：外部 spectator 跟车

```bash
cd ~/CARLA/CarlaAir-v0.1.7/code
source ~/miniconda3/etc/profile.d/conda.sh
conda activate carlaAir

python3 - <<'PY'
import math
import time
import carla

client = carla.Client("localhost", 2000)
client.set_timeout(5.0)
world = client.get_world()
spectator = world.get_spectator()

while True:
    ego = None
    for actor in world.get_actors().filter("vehicle.*"):
        if actor.attributes.get("role_name") == "ego":
            ego = actor
            break
    if ego is not None:
        tr = ego.get_transform()
        yaw = math.radians(tr.rotation.yaw)
        loc = tr.location + carla.Location(
            x=-18.0 * math.cos(yaw),
            y=-18.0 * math.sin(yaw),
            z=16.0,
        )
        spectator.set_transform(
            carla.Transform(loc, carla.Rotation(pitch=-32.0, yaw=tr.rotation.yaw))
        )
    time.sleep(0.05)
PY
```

## 当前边界与后续

当前 UAV-BEV 是轻量 BEVFormer-Lite 风格特征，不是完整训练版 BEVFormer。

当前融合方式是低幅度 steer correction，不是端到端 joint planner。

当前车端 TCP-Lite 负责局部驾驶，YOLO11n 负责安全感知，无人机提供轻量全局 BEV-like 道路上下文并小幅修正方向；无人机已经真实参与控制，但目前是辅助增强。

当前无人机偶尔会乱飞 这是一个小问题

后续推进：

阶段 A：评估与数据闭环
  -> 统一记录 clean 场景数据
  -> 建立 no-UAV / UAV-fusion 对照
  -> 明确当前系统短板

阶段 B：融合训练数据集
  -> 记录 ego RGB / speed / command / TCP trajectory
  -> 记录 UAV RGB / BEV-like feature
  -> 记录 control / lane offset / safety diagnostics
  -> 形成 fusion dataset

阶段 C：小型 fusion planner
  -> 输入车端局部状态 + UAV-BEV feature
  -> 预测 steer correction 或 local waypoint correction
  -> 离线训练 + clean 场景真实验证

阶段 D：RL 任务环境
  -> 基于当前 active_world 封装 gym-like env
  -> 定义 observation / action / reward / done
  -> 先做 safety shield 下的 residual RL

阶段 E：更强 BEV backbone
  -> 等 fusion planner 证明有效后
  -> 再引入真正 BEVFormer backbone

当前：

```text
车载 RGB + speed + navigation_command
  -> TCP-Lite
  -> 预测局部 trajectory
  -> 转成 steer / throttle / brake

车载 RGB
  -> YOLO11n
  -> obstacle / traffic diagnostics
  -> safety gate

UAV RGB
  -> UAV-BEV Lite 特征提取
  -> road_confidence / center_bias / forward_density / left_right_balance
  -> 小幅 steer correction

TCP-Lite 主控制 + YOLO safety gate + UAV-BEV correction
  -> ego vehicle control
```

## 6. 本次新增：三档 UAV 融合对比闭环

已经把 UAV 融合从隐式 boolean 升级为显式三档模式：

```text
uav_fusion_mode = none
  -> TCP-Lite + YOLO
  -> 不读取 UAV-BEV correction

uav_fusion_mode = rule
  -> TCP-Lite + YOLO + 当前 UAV-BEV 规则残差
  -> 使用 road_confidence / center_bias 做小幅 steer correction

uav_fusion_mode = learned
  -> TCP-Lite + YOLO + 学习式 fusion planner 残差
  -> 只预测 steer correction，不输出 throttle/brake，也不接管 TCP-Lite 主控制
```

兼容旧配置：如果旧 JSON 只写了 `uav_bev_fusion_enabled=true`，会自动映射为 `rule`；如果没有开启 UAV-BEV，则映射为 `none`。

学习式 planner 当前先落地为 JSON 版线性残差模型：

```text
models/fusion_planner_linear.json
```

它的定位不是最终模型，而是先固定接口、诊断字段和限幅行为。后续训练得到的小型 MLP / torch checkpoint 可以复用同一层 `FusionPlannerAdapter`，但仍然只输出 residual correction。

第二步：加入会车和行人，验证 UAV 全局视角是否提前给出风险上下文。

第三步：用 clean + 单因素复杂场景记录的数据训练小型 fusion planner，输出 steer correction 或 local waypoint correction；初期仍建议只启用 steer correction。

第四步：正式对比 `no_uav`、`rule_uav_bev`、`learned_fusion` 三组：

```bash
python3 scripts/evaluate_fusion_benchmark.py \
  --input-dir recordings/fusion_benchmark \
  --output-dir reports/fusion_benchmark
```

第五步：当 learned fusion 在 clean 和单因素复杂场景中不破坏稳定性，并且能降低碰撞率、车道偏移、路口摇摆或提升场景通过率后，再考虑 residual RL。
