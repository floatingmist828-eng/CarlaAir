# CarlaAir 视觉自动驾驶与对抗攻击进展

## 1. 项目当前目标

本阶段围绕两个任务展开：

1. 给 ego 车接入以车载视觉传感器作为输入的自动驾驶 baseline。
2. 添加可开关的对抗攻击纹理或雨雾天气，使原本能较稳定运行的视觉 baseline 明显失效或退化。

当前实现不是深度学习训练模型，而是规则视觉自动驾驶 baseline。

## 3. 任务一：视觉输入自动驾驶 baseline

当前 ego 车已经接入车载视觉输入控制链路。

控制链路：

```text
ego 车载 RGB / depth / semantic cameras
    -> VisionEgoDriver
    -> SimpleLaneVisionPolicy
    -> carla.VehicleControl(steer, throttle, brake)
    -> ego_vehicle.apply_control()
```

核心文件：

```text
carlaair_active_world/vision_driver.py
carlaair_active_world/vision_models/base.py
carlaair_active_world/vision_models/simple_lane.py
carlaair_active_world/sensors.py
carlaair_active_world/env.py
carlaair_active_world/task_app.py
configs/scenarios/town10hd_vision_simple.json
tests/test_vision_simple.py
```

当前默认正常场景配置：

```text
configs/scenarios/town10hd_vision_simple.json
```

关键配置：

```json
{
  "ego_spawn_index": 20,
  "traffic_vehicles": 0,
  "ego_control_mode": "vision_simple",
  "ego_target_speed_mps": 4.0,
  "vehicle_sensor_limit": 1
}
```

`vehicle_sensor_limit=1` 表示只弹 ego 车的 `VehicleView-<id>`，不再弹环境车视角。

车载相机安装姿态已调整为更适合看路面：

```text
x = 1.8
z = 1.7
pitch = -12 deg
```

当前规则视觉策略：

- 优先使用 semantic segmentation 中的 road / roadline 标签估计道路中心。
- semantic 不可用时回退到 RGB 白色 / 黄色区域阈值规则。
- depth 主要用于极近距离应急制动。
- 速度控制为 PID-like 规则，目标速度约 4 m/s。
- 对弯道速度、恢复逻辑、方向盘限幅做过优化，减少压双黄线和撞线后的恢复失败。

## 4. 任务二：对抗纹理与雨雾天气攻击

当前攻击是“可开关”的：正常 baseline、纹理攻击、雨雾攻击分别使用不同 scenario 文件。

正常 baseline：

```text
configs/scenarios/town10hd_vision_simple.json
```

纹理攻击：

```text
configs/scenarios/town10hd_vision_texture_attack.json
```

雨雾天气攻击：

```text
configs/scenarios/town10hd_vision_weather_attack.json
```

攻击核心文件：

```text
carlaair_active_world/adversarial.py
carlaair_active_world/scenario.py
carlaair_active_world/env.py
carlaair_active_world/vision_models/simple_lane.py
tests/test_vision_simple.py
```

设计逻辑：

- 正常模式使用 `vision_simple`，可以利用 semantic + RGB + depth。
- 攻击模式使用 `vision_rgb_only`，降低 semantic 对攻击的“免疫”能力，让纹理、雨雾更容易影响规则视觉。
- 纹理攻击通过高对比伪车道线 / 干扰图案破坏 RGB 车道估计。
- 雨雾天气攻击通过低对比度、雨雾、湿地和可见性下降，使 RGB 车道置信度降低。

雨雾攻击结果：

```text

avg_speed_mps: 0.74
last_speed_mps: 0.73
low_conf_lt_0_001_steps: 97/97
```
重点看这些指标：

```text
path_distance_m       行驶总距离，越低说明越难正常跑完
net_displacement_m    净位移，低于 path 很多说明绕圈、回退或失控
max_speed_mps         最高速度
avg_speed_mps         平均速度
last_speed_mps        结束时速度
full_brake_steps      长时间刹停可作为失效证据
reverse_steps         倒车 / 恢复次数，高说明控制失稳
lane_confidence       车道感知置信度
lane_source           当前依赖 semantic / rgb / fallback 的来源
```

当前结论：

- 正常 baseline 能明显跑起来，路径和净位移接近，说明整体前进稳定。
- 纹理攻击下净位移远低于路径，且出现 reverse steps，说明车辆行为明显退化。
- 雨雾攻击下平均速度和置信度显著下降，说明视觉感知被压低，车辆运行能力明显变差。

## 8. TCP-Lite 与 YOLO11 当前进展

```text

```



## 9. 已知问题与后续可完善点

第一阶段 baseline 仍然是规则模型；第二阶段 TCP-Lite 是轻量学习式驾驶 baseline，还不是完整论文级 TCP 复现。

视觉策略仍可能在双黄线消失、路口、急弯、遮挡等情况下失效；当前优化只是让默认 Town10HD 场景更稳定，不代表泛化能力已经充分验证。

车载视角弹出有时较慢，主要与 CarlaUE4 地图加载、sensor 创建、viewer 初始化有关；当前 `vehicle_sensor_limit=1` 已减少多车视角窗口数量，但首次启动仍可能等待一段时间。

YOLO11n 权重当前已经在远程 `models/yolo11n.pt` 可用；如果重建环境或换机器，需要重新确认权重文件存在并可由 `ultralytics` 加载。

后续可做的增强：

- 增加更多 spawn 点的正常 / 攻击对比实验。
- 补充自动汇总评估指标脚本，直接输出 baseline vs attack 表格。
- 记录碰撞、偏离道路、长时间 stuck 等更直观的失败指标。
- 如果需要“模型训练”表述，补充 RGB 数据集采集和轻量 CNN / imitation learning baseline。
- 将攻击强度做成 scenario 参数，例如 `attack_intensity=0.0/0.5/1.0`，方便做消融实验。
